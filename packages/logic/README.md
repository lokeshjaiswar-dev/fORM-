# @form/logic

The `logic@2` engine (FND-06, `docs/platform/02-form-schema-v2.md` §3.3): `compile()` turns a definition into a plan of steps over cells, `evaluate()` runs that plan in one pass. Pure and isomorphic: no React, DOM, Node built-ins, clock, randomness or host locale, and no host Unicode tables except NFC (`String.prototype.normalize`, the accepted exception in schema §3.1, BL-075), so the browser, the API and the worker compute the same bytes.

| Path | What it holds |
|---|---|
| `src/cells.ts` | Cell keys (`visible:`, `onPath:`, `enabled:`, `required:`, `value:`, …) and step keys used by `CompiledForm.reads` and traces |
| `src/structure.ts` | Placement (document order, parents, pages) and the cells a `value(b)` read implies: `visible` of b and its ancestors, `onPath` of its page |
| `src/analyze.ts` | Steps, reads and writes: one `on_path` step per page, `capture` steps for hidden fields, one step per enabled rule (`then` and `else` targets) |
| `src/subset.ts` | Static typing of the P0 subset against the registry's `paths` and `operators`; everything outside it is `missing_capability` |
| `src/plan.ts` | The step graph with same-cell writer edges in authored order, and Kahn's sort (ties: rule index, then render order) |
| `src/cycles.ts` | `logic_cycle` with the cycle's path, and the "conflicting writers" hint when a writer edge closes it |
| `src/pageOrder.ts` | I8, transitively through every cell read, and `validation_bound_page_order` for date bounds on another block |
| `src/taint.ts` | I13: classification and purposes of every derived cell |
| `src/validateDefinition.ts` | `validateDefinition(def, mode, registry)`: structure, registry lints, the P0 subset, cycles, page order, `initially_hidden_never_shown` |
| `src/compile.ts` | `compile(def, registry)` → `CompiledForm` (plan, reads, requires, data inventory, taint, `definitionHash`) |
| `src/evaluate.ts` | `evaluate(version, answers, meta, scope, { trace })` and `createEvaluator` for incremental client updates |
| `src/operators.ts`, `src/text.ts`, `src/decimal.ts` | Condition operators; NFC + generated case fold + pinned grapheme length; decimal.js (full) at precision 34 |
| `src/casefold.generated.ts` | Simple case folding (CaseFolding.txt C + S, Unicode 17.0.0, the segmenter's version), generated by `scripts/gen-casefold.ts` |
| `src/projectForRuntime.ts` | The runtime projection: no notes, origin stamps or server actions; client steps and their `reads` only |
| `src/trace.ts` | LOG-22 trace rows and `evalStateJson`, the canonical bytes the determinism job compares |

## Rules

- **P0 subset.** Condition groups with every comparison operator (dates included); actions `show`, `hide`, `require`, `unrequire`, `enable`, `disable`; `Expr` limited to `lit`, `ref` and comparisons; hidden fields from URL parameters, UTM tags, static text or such expressions. Everything else (other actions, functions, variables, relative dates, `matches_preset`, row scopes) is `missing_capability` until WP-2.01–2.03.
- **`compile()` refuses fatal issues** (ADR-0002 §2) and reports them as errors: any error and any `missing_capability` (a registry stub's lint or logic outside the subset). `validateDefinition(…, 'save')` reports the same lints and capabilities as warnings, so drafts stay editable.
- **B21: a rule whose condition reads a deleted block is disabled**, as migration does (schema §4.2): compile leaves it out of the plan and its targets keep their initial state. The dangling id stays a draft warning and a publish error (I4), so it never blanks the builder preview. A hidden value whose expression reads a deleted block reads null.
- **Hidden values.** URL and UTM captures keep a resumed answer when the parameter is absent. Static and expression captures are authoritative: a submitted value never replaces them, and they are absent when the source yields nothing (a hidden or unanswered source reads null, LOG-09).
- **Null in conditions is false**, except through the null-safe `eq` / `neq` and `is_not_answered`, and the negated operators `not_contains`, `not_starts_with`, `not_ends_with` and `includes_none`, which are true on an unanswered left side, as in v1 (schema §3.1).
- **Inputs are immutable.** `evaluate` prepares the plan once per `version.compiled` object and parses each answer's twin once per answer object (both cached by identity). Never mutate a version, an answer map entry or an `AnswerValue` in place; build a new object for every change, as `createEvaluator(…).update` callers do anyway.
- **Answers are read only through `answerScalar(block, value, path)`.** An answer that fails its twin, an unknown block or a block that is not effectively visible reads as unanswered; the trace says why.
- **Last write wins in authored order** among writers of one cell, whatever the other dependencies; a writer edge that closes a cycle is a `logic_cycle` with the conflicting-writers hint.
- **`evaluate` never throws** on answers or metadata (fuzzed); it throws only for a version compiled by another engine.
- **Incremental equals full.** `createEvaluator(…).update(answers, changed)` re-runs only the steps downstream of the changed values (fuzzed against full passes).
- **Determinism is tested in four engines.** `test/corpus/determinism.ts` (35 v1 parity forms × 200 answer sets, random P0 forms, text and decimal edge cases, the `@form/i18n` grapheme corpus) runs in Node (`test/determinism.test.ts`, digest pinned) and in Chromium, Firefox and WebKit (`pnpm test:determinism`, CI job `determinism`), and every EvalState JSON must be byte-identical. A change to the digest is a semantic change: a new engine id, not an edit.
- **Performance.** `test/perf.test.ts` (300 blocks, 200 rules) targets a full evaluation under 5 ms p95 and an incremental update under 1 ms p95 in Node. It runs only through `pnpm test:perf` (`vitest.perf.config.ts`: no coverage, one file at a time, CI job `determinism`), never inside the coverage run of `pnpm test`. Each measurement runs five trials after a warm-up and asserts on the best trial's p95 against the target × `FORM_PERF_SLACK` (default 2); every trial is printed with "meets" or "MISSES" against the real target. No timed run reuses an answer object, so every answer's twin is parsed as in a submission.
  - The 5 ms target is for evaluating a **loaded** version on fresh answers. The prepared plan is cached per `version.compiled` object, so callers keep loaded versions in memory: the submission pipeline (WP-1.12, architecture §2.5 "load … the version (cached)") and the runtime (WP-1.09, the immutable `RuntimeFormVersion` LRU of §4.1) hold one object per version id, and the client keeps its version for the session.
  - The **cold** case (a freshly parsed version and fresh answers: plan preparation plus the first evaluation) is measured and printed against the same target, but asserted only against 4 × the target × `FORM_PERF_SLACK` (40 ms by default), a guard against gross regressions. Measured locally it is 2–3 times the loaded-version cost (best p95 6–8 ms against 2.7–3 ms), so it misses the 5 ms target.
- **v1 parity.** `test/parity.test.ts` checks show/hide against the v1 `isBlockVisible` (`test/corpus/v1.ts`, commit `e1be409`) on 35 forms × 200 answer sets; the only differences allowed are the named fixes there (transitive hiding, B21, unanswered is not 0, unmatched choice values). It runs twice: over the oracle's own 35 forms (`toV2`, which keeps B21 rules for `compile()` to disable), and over the `migrate()` output of the WP-0.05 corpus (`@form/schema/migration-fixtures`), where the rules migration turns off are named per fixture. `test/migrate.test.ts` checks that every migrated fixture passes `validateDefinition(…, 'save')`, compiles and fits its registry config schemas.

```sh
pnpm --filter @form/logic typecheck
pnpm --filter @form/logic test                 # unit, golden, parity, fuzz, purity, Node determinism (with coverage)
pnpm test:perf                                 # the benchmark, alone and without coverage; prints every trial's p95
pnpm --filter @form/logic exec playwright install chromium firefox webkit   # once
pnpm test:determinism                          # the corpus in Chromium, Firefox and WebKit, diffed with Node
pnpm --filter @form/logic casefold --check     # the case-fold table matches scripts/data/CaseFolding-17.0.0.txt
```
