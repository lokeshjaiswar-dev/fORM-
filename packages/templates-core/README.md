# @form/templates-core

The template engine (TPL-03, WP-T0.2; `docs/platform/06-templates.md` §3–4): `instantiate()`, `insertSnippet()`, `resolveVariables()` for `bake` variables, optional parts, `lockFingerprint()` (implemented, not enforced until P3) and the pure parts of `sanitizeForTemplate()`. Pure and isomorphic like `@form/logic`: no React, DOM, Node built-ins, clock, randomness, host locale or Unicode tables, so the offline builder and the API produce the same bytes from the same `Idempotency-Key`.

| Path | What it holds |
|---|---|
| `src/instantiate.ts` | `instantiate(version, ctx, options?)`: a `form` template → `{ definition, ops, bindings, workflow?, warnings }` |
| `src/snippet.ts` | `insertSnippet(version, form, at, ctx, options?)` → `DocumentOp[]`, `keyMap`, binding; `applyDocumentOps(form, ops)` |
| `src/variables.ts` | `resolveVariables` (bake values from Use-dialog answers, org profile per locale, brand kit, form, declared defaults), `bakeVariables`, `variableNames`, `orgValue` |
| `src/parts.ts` | `applyOptionalParts`: removes parts whose `when` is false, with everything they list and every reference to it |
| `src/remap.ts` | Id and key remapping over v2 JSON (`remapRefs`, `remapTextKey`, `remapOf` / `inverseRemapOf`) |
| `src/lock.ts` | `lockFingerprint` (block, theme, ending, purpose locks) and `opsLockFingerprint` (email, PDF locks) |
| `src/sanitize.ts`, `src/pii.ts` | `sanitizeForTemplate` and `scanPii` (email, Indian phone, PAN, Aadhaar with Verhoeff, GSTIN) |
| `src/uuid.ts` | RFC 9562 `uuidv5` over `@noble/hashes` SHA-1, `seedNamespace` |

## Rules

- **Ids.** Every block, page, ending, rule, rule group, logic variable, purpose and condition gets `uuidv5(seedNamespace(ctx.idSeed), name)`. The name is the source id for blocks, pages and endings (one namespace, I1) and `<namespace>:<sourceId>` for the others (`rule:r1`, `rule_group:g`, `variable:v`, `purpose:p`, `condition:c`); the same strings key `binding.idMap`. A seed that is a UUID is the namespace itself; any other seed is hashed into one under `SEED_NAMESPACE`. Items a ref adds (its ending, notification, PDF, workflow) use names with a `/` (`refs/endings/0`), which no source id can have. Binding ids come from `ctx.bindingIdSeed` the same way. Option, matrix-row, consent-item and product ids are scoped to their block and kept.
- **References.** `remapRefs` maps every reference site `validateStructure` checks (I4): element ids under `blockId`, `target(s)`, `children`, `atPage`, `pageId`, `endingId`, `defaultEndingId`, `repeatingGroupId`, `*BlockId`, skip actions' `from` / `to` and an answers table's `include`; `varId`; `purposeId(s)`; rule `groupId`; condition ids; `carryKeys` / `keys` through the key map. Translation keys are remapped with `remapTextKey`. `x-*` extensions and an unsupported block's `raw` are copied verbatim.
- **Origin stamps** (`{ bindingId, sourceId }`) go on every block, page, rule, logic variable, ending and purpose, and on the ending, status screen, notification and PDF a ref adds (`sourceId: '$root'`). Copying never keeps a source form's stamps.
- **Variables.** A `var` node bakes when its variable is declared `bake`, or is an undeclared `custom.*`; the node becomes a text node (plain templates: a string) and adjacent text runs merge. A baked variable without a value uses its `fallback`, else the node stays and `variable_missing` is reported (also for any required `bake` variable without a value). Live variables stay as nodes for the builder and publish. Org-profile text is resolved per locale (`localized`, then the base field).
- **Optional parts** are applied on the template's source ids before remapping, to the definition and to every applied ref (`pruneRemoved`). Rules that read a removed block or variable, or lose every action, are removed (`part_removed_rule`); pipes to a removed block become their fallback text; date bounds, field recipients, reply-tos, optional anchors (`anchorBlockId`, a guardian's evidence field and page, billing fields), PDF password sources and answers-table entries on it are dropped; a workflow branch that reads it is dropped and an approver field becomes the form owner (both reported). A required reference that cannot be pruned (an age gate's `dobBlockId`, a guardian's email field) stays and is reported at its pointer, as is a recipient list left empty.
- **Refs.** Applied when `ctx.include` allows: a theme replaces `definition.theme` (with `presetRef` when it came from a `TemplateRef`); a `thank_you` ending is appended to `definition.endings`, other ending roles fill `ops.screens` (the first wins; a later one for the same role is skipped with `feature_unavailable`); `notification`, `autoresponder` and `edit_notice` emails become `ops.notifications` (the other roles are system emails: skipped with `feature_unavailable`); PDFs become `ops.pdfTemplates`; a workflow is returned as `workflow`. Each applied ref has its own binding. A `TemplateRef` is looked up with `options.resolveRef`; without one it is skipped with `feature_unavailable`.
- **Never copied:** access control, integrations, webhooks, analytics ids (`behavior.analytics`), prefill links and submissions. Encryption and PII tags are copied.
- **Locales.** The draft keeps the template's locales that are its default, `ctx.locale` or `ctx.extraLocales`; a requested locale the template lacks is reported (`locale_incomplete`). Translations are copied with `origin: 'template'`; `tplvar:` messages stay with the template.
- **Bindings** need an org and a user, which `InstantiateContext` does not carry: pass `options.actor`. Without it the bindings use `OFFLINE_ACTOR` (the offline builder; the API re-runs `instantiate` with the real actor and writes the binding rows).
- **Snippets.** `insertSnippet` inserts after `at.afterBlockId` (in its page or container) or at the snippet's preferred position on `at.pageId`; refuses a second copy of a `oncePerForm` snippet (`snippet_already_inserted`): with `options.bindings` (the form's template bindings) an earlier copy is a snippet binding of the same template whose root is still in the form; without them, any block of the root's type stamped with the root's source id. A snippet whose default locale is not the form's is inserted with its translations into the form's default locale, and its own inline text becomes that locale's messages (`locale_incomplete` when it has no text in the form's default locale). Clashing keys get `_2`, `_3` … (`key_renamed`); `keyMap` maps every snippet key. A purpose with the same notice content as one the form declares is reused. The ops are the subtree's `add_block`s in pre-order (the root with its children already listed; each descendant names its parent and index), then `add_rule`, `add_variable`, `add_purpose` and one `set_messages` per form locale. `applyDocumentOps` is the reference implementation of those ops.
- **Lock fingerprints** hash `{ v: LOCK_FINGERPRINT_VERSION, target, modes, projection }` with JCS + SHA-256. Ids and keys are mapped back to source ids through the binding and live `var` nodes are reduced to their names, so a fresh instance has the template payload's fingerprint (taken with an empty `idMap`). Content that holds a **baked** variable cannot match (the value is in the text); lock such content with live variables. Email and PDF locks live in FormOps: `lockFingerprint` refuses them and `opsLockFingerprint` takes them.
- **Sanitiser.** Placeholder `formId` (`TEMPLATE_FORM_ID`), no origin stamps, no access, analytics, webhooks or integrations; notifications, PDF templates and status screens become inline refs; literal recipients become the form-owner placeholder (each literal address is a hit); org-profile values become `org.*` variable nodes; every other email, phone (`+91`, `0091`, `0`, bare `91` or no prefix), PAN, Aadhaar (Verhoeff-checked) and GSTIN in author text, and anywhere in the `x-*` extensions and unsupported-block `raw` payloads that are copied verbatim, is a `piiHits` entry for the author to clear or acknowledge. The patterns are anchored and length-bounded, so a scan is linear in the text (it runs server-side on author input). Asset references, PII re-tagging and taint are the server's part.

```sh
pnpm --filter @form/templates-core typecheck
pnpm --filter @form/templates-core test                # unit, property (fast-check), the 42-case PII corpus, purity, Node determinism digest
pnpm --filter @form/templates-core test:determinism    # the corpus in Chromium, Firefox and WebKit, diffed byte-for-byte with Node
```

The browser leg reuses the engines `pnpm --filter @form/logic exec playwright install chromium firefox webkit` installs. A change to the pinned digest in `test/__snapshots__/determinism.test.ts.snap` changes the ids clients and servers derive from one `Idempotency-Key`: treat it as a format change.
